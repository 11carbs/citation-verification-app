# 資料格式說明（方法 A prototype）

第二人的交付之一，給第一人和第三人接手用。對應分工 PDF「訂資料格式（最先做）」。

程式碼位置：`src/schemas.py`（共用型別）、`src/adapters.py`（兩人交接的介面）。以 code 為準，這份是對照表。

更新：2026-11-22

## 一、資料怎麼流

```
使用者貼上段落 ＋ ref 清單
        ↓  第一人：拆句、抓引用編號、對應 ref
  CitationPair（一個引用配對一筆）
         ↓  第二人的解析程式在本機抽篇名/DOI/網址
         ↓  第三人：Jev Q1 判斷篇名
         ↓  「不相關」直接輸出不支持。其餘交第二人查摘要
  ReferenceLookupResult
         ↓  第三人：Jev Q2 有摘要用摘要，否則用篇名
  JevJudgmentResult
        ↓  第三人：整理
  MethodResult → AnalysisRow → 表格與 CSV
```

串接的地方在 `src/pipeline.py` 的 `run_method_a_pipeline()`。

## 二、第一人交給第二人：`CitationPair`

| 欄位 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `pair_id` | str | 無 | 這筆配對的識別字串 |
| `claim_text` | str | 無 | 送入 Jev 的陳述。一般保留原句；可明確分隔且各有句尾引文時，用各引文所屬子句。可拆分的句尾共引句使用個別子主張。**不可被硬換行截斷** |
| `citation_marker` | str | 無 | 原文的引用標記，例如 `[47]` |
| `ref_number` | int | 無 | 引用編號 |
| `ref_raw` | str | 無 | ref 清單裡那一條的原文，保留原始換行 |
| `is_compound` | bool | False | **以句子為單位**：該句引用數 > 1 就是 True |
| `match_status` | ReferenceMatchStatus | 已配對 | 內文有編號但清單沒有 → `MISSING_REFERENCE` |
| `error_message` | str | 空字串 | 解析階段的錯誤說明 |
| `original_claim_text` | str | 空字串 | 按各自引用拆成子句，或拆成共引子主張時保留的原句 |
| `claim_group_id` | str | 空字串 | 同次輸入中，來自同一句的共引子主張使用同一識別碼 |

`match_status` 是 `MISSING_REFERENCE` 時，`pipeline` 直接建立只有 pair 的 `AnalysisRow`，不會往下查。

第一版處理兩個明確命名的對象共用簡單類別敘述的句型，例如 `X and Y are pretrained language models [1], [2].`。每個子主張與句尾的每一篇候選文獻各建立一筆配對。各自帶引用的子句沿用對應的引用編號。

## 三、第二人交給第三人：`ReferenceLookupResult`

| 欄位 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `ref_number` | int | 無 | 對應回 `CitationPair.ref_number` |
| `title` | str | 無 | 從 ref 抽出的篇名。抽不到時是空字串 |
| `doi` | str | 空字串 | 小寫 |
| `url` | str | 空字串 | — |
| `abstract` | str | 空字串 | 拿不到時是空字串 |
| `source_status` | SourceStatus | 待查詢 | 見下方列舉值 |
| `error_message` | str | 空字串 | 只有「查不到」與「查詢失敗」會填 |
| `source_note` | str | 空字串 | 查詢經過，每一步都記，成功也會記 |
| `abstract_source` | str | 空字串 | `semantic_scholar` 或 `openalex` |

以 DOI、arXiv ID 或篇名查 Semantic Scholar。無可用摘要時統一嘗試適用的 ACL Anthology、arXiv、Crossref、Europe PMC 和 OpenAlex，查到可採用的摘要就停止。沒有官方摘要可以對照時，索引摘要會標記完整性未經官方核對。

ACL Anthology 的新式及舊式 DOI 都可辨識出對應的 Anthology 編號。這類文獻會先用該編號向 Semantic Scholar 查詢，無對應紀錄時再用原 DOI。限流時以同一編號讀取 ACL Anthology 官方摘要，並核對 DOI 和篇名。OpenAlex 仍使用原 DOI。 [ACL DOI 規則](https://aclanthology.org/faq/doi/)

## 四、第三人交回來：`JevJudgmentResult`

| 欄位 | 型別 | 限制 |
|---|---|---|
| `title_choice` | TitleRelevance 或 None | 相關／不確定／不相關，Q1 無結果時留空 |
| `title_probabilities` | dict[str, float] | 每個值 0.0–1.0，總和必須是 1.0（容差 0.01）。Q1 無結果時為空 |
| `confidence` | float 或 None | 0.0–1.0，Q1 無結果時留空 |
| `support_score` | float 或 None | Q2 的有效分數為 **0.1–0.99**。停止或失敗而無分數時留空 |
| `evidence_basis` | EvidenceBasis 或 None | 實際用到的判斷依據，方法 A 原型使用篇名或摘要 |

`support_score` 和 `confidence` 的範圍在 `__post_init__` 檢查，寫錯會當場報錯，不會悄悄過去。

## 五、最後的 `MethodResult`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `support_score` | float 或 None | None 代表沒有判斷（例如缺 ref） |
| `evidence_basis` | EvidenceBasis 或 None | — |
| `source_status` | SourceStatus | 從 `ReferenceLookupResult` 帶過來 |

`MethodResult.band` 依分數換算三級。Q1 判不相關時，直接用「不支持」分級，Q2 分數留空。

| 證據層級 | 支持分數 |
|---|---|
| 支持 | 0.70（含）以上 |
| 不確定 | 0.40（含）以上、未滿 0.70 |
| 不支持 | 未滿 0.40 |

門檻寫在 `src/schemas.py` 的 `support_band()`，依 11/17 紀錄。

## 六、列舉值

全部是 `StrEnum`，值會直接顯示在畫面上，不要自己寫字串。

| 列舉 | 值 |
|---|---|
| `SourceStatus` | 拿到摘要 / 有文獻但沒摘要 / 查不到 / 查詢失敗 / 待查詢 / Q1 停止未查詢 |
| `EvidenceBasis` | 篇名 / 摘要 / 全文 / 書目資料 / 無可用證據 |
| `SupportBand` | 支持 / 不確定 / 不支持 |
| `ReferenceMatchStatus` | 已配對 / 缺少 ref |
| `TitleRelevance` | 相關 / 不確定 / 不相關 |

### 兩個容易混的名字

**`EvidenceBasis`（判斷依據）** 是「用什麼證據判斷的」——篇名、摘要、全文。

**`SupportBand`（證據層級）** 是「判斷結果是哪一級」——支持、不確定、不支持。

11/17 紀錄裡的「證據層級」指的是後者，所以畫面上 `SupportBand` 顯示成「證據層級」，`EvidenceBasis` 顯示成「判斷依據」。

### `SourceStatus` 的「查不到」與「查詢失敗」不可混用

| 狀態 | 意思 |
|---|---|
| 查不到 | 這次查詢未找到可確認的資料，不代表文獻不存在 |
| 查詢失敗 | 被限流或連不上，**沒有查成功** |

查詢失敗不代表文獻不存在。評估時這兩種要分開計數，否則「沒查成功」會被算成「內容不支持」。

## 七、輸出欄位

`AnalysisRow.to_record()` 產生，`src/presentation.py` 的 `OUTPUT_COLUMNS` 定義順序。表格和 CSV 共用同一份。

| 欄位 | 來自 |
|---|---|
| pair_id | CitationPair |
| 引用陳述 | CitationPair.original_claim_text，缺少時使用 CitationPair.claim_text |
| 引用標記 | CitationPair.citation_marker |
| ref 編號 | CitationPair.ref_number |
| 被引文獻 | CitationPair.ref_raw |
| ref 配對狀態 | CitationPair.match_status |
| 錯誤狀態 | 配對、來源查詢與 Jev 的錯誤說明 |
| 來源狀態 | MethodResult.source_status |
| 方法 A 摘要來源 | 本次使用的摘要來自 Semantic Scholar 或 OpenAlex。只使用篇名時留空。 |
| 方法 A 支持分數 | MethodResult.support_score |
| 方法 A 證據層級 | MethodResult.band（自動換算） |
| 方法 A 判斷依據 | MethodResult.evidence_basis |
| 方法 A 篇名判斷 | JevJudgmentResult.title_choice |
| 方法 A 判斷狀態 | JevJudgmentResult.status |
| 摘要查詢紀錄 | ReferenceLookupResult.source_note。用到 OpenAlex 時也可看到 Semantic Scholar 的查詢結果。 |
| 方法 B 支持分數 | 同上，方法 B 的 |
| 方法 B 證據層級 | 同上 |
| 方法 B 判斷依據 | 同上 |
| 方法 A 查核紀錄 | CSV 使用。保存 Q2 實際送出的證據文字、摘要來源、模型版本、請求 ID 與原始分數。Q2 若沒有有效結果，這欄留空。 |
| 方法 A 摘要節錄 | 網站上對有摘要且整句未達支持的配對補查一次，由 Jev 從原摘要的句子中選一段可核對的內容。補查結果及請求編號記入查核紀錄，整句分級仍由 Q2 決定。 |
| 共引群組 | CitationPair.claim_group_id |
| 查核子主張 | 拆分後實際查核的 CitationPair.claim_text |
| 共引摘要涵蓋 | 有至少一篇摘要取得「支持」的子主張數／共引子主張總數 |
| 共引待查數 | 尚未有摘要支持，且仍有候選文獻缺少摘要查核結果的子主張數 |

共引欄位追加於 CSV 末尾。逐筆欄位由 `to_record()` 建立，群組涵蓋與待查數由 `build_output_dataframe()` 填入。

網站以摘要執行 Q2 時，另傳已核對書目的篇名，以辨識摘要開頭的「本規格」等指稱。篇名在這條路徑只供辨識文件，查核紀錄保存送入的 `verified_source_title`。
